# Decisions and deviations from the spec

This file records every place where the build differs from, or had to interpret, `SMART_SPLIT_SPEC.md`, and why.

| # | Topic | Decision | Why |
|---|---|---|---|
| 1 | Repository root | The project folder (`blcnProj/`) is the repo root, playing the role of `smart-split/` in the spec. `SMART_SPLIT_SPEC.md` stays at the root. | The spec was placed in this folder with instructions to build here. |
| 2 | Hardhat version | **Hardhat 3.19.0** with `@nomicfoundation/hardhat-toolbox-mocha-ethers` 4.0.0 (ethers v6 + Mocha + Chai). TypeScript, ESM (`"type": "module"`). | Current stable release (`npm view hardhat` → 3.19.0, `latest` tag), and the spec asked for the current stable version. The config uses Hardhat 3's `defineConfig` / `configVariable` format. |
| 3 | Network names | Networks are `default` (in-process), `localhost` and `sepolia`. | Hardhat 3 renamed Hardhat 2's in-process `hardhat` network to `default`. Same chainId (31337), same role. |
| 4 | Secrets | `configVariable("SEPOLIA_RPC_URL")` / `("SEPOLIA_PRIVATE_KEY")`. These resolve from the **encrypted Hardhat keystore** (`npx hardhat keystore set …`, recommended) or from environment variables. `hardhat.config.ts` also loads an optional git-ignored `.env` with Node's built-in `process.loadEnvFile` (no `dotenv` dependency). | Hardhat 3 has a built-in keystore and does not read `.env` itself. Both options from the spec are supported. |
| 5 | Coverage and gas report | Uses Hardhat 3's **built-in** `--coverage` and `--gas-stats` flags (`npm run coverage`, `npm run gas`), instead of `solidity-coverage` / `hardhat-gas-reporter`. | Those two plugins target Hardhat 2. Hardhat 3 ships equivalent features. |
| 6 | Chai matcher API | Hardhat 3 deprecated `.to.be.reverted`. Tests use `.revertedWithCustomError(...)` and `.revert(ethers)`, and `changeEtherBalances(ethers, accounts, deltas)` takes `ethers` as its first argument. | Required by the current matcher library. No test was weakened. |
| 7 | `export-abi` runtime | Runs with plain `node` (Node ≥ 22.18 strips TypeScript types natively), after `hardhat compile --quiet`. The `--address/--block/--chain` flags are parsed with `node:util.parseArgs`. | `hardhat run` does not pass custom CLI flags to scripts. Plain Node also works after a Remix deployment. **Node 22.18+ is therefore required** (Hardhat 3 needs Node 22 anyway). |
| 8 | Extra test helpers | Added `GasHeavyReceiver` (its `receive()` writes to storage, so it needs more than 2300 gas) and `TransferSender` (pays with `transfer`). They live in `contracts/test-helpers/GasHeavyReceiver.sol`. | Needed for the "smart-contract-wallet recipient" test in §4.2. The contrast test shows that `transfer()` **fails** for the same recipient, which shows why `call` is used. |
| 9 | `ReentrantReceiver` field name | The re-entry target is stored as `reentryTarget` (not `target`). | `target` clashed with ethers v6's `BaseContract.target` in the generated TypeChain types (TypeScript error). |
| 10 | Reentrancy test behaviour | `ReentrantReceiver` catches the failed re-entry (`try/catch`) and records it, so the **outer payment succeeds** and the nested call is rejected with `ReentrantCall()`. | The spec asked for "tx outcome matches the documented behaviour". This is the documented behaviour. A receiver that does *not* catch would make the whole payment revert (`TransferFailed`), which the atomicity test already covers. |
| 11 | Remix vs Hardhat bytecode | **Verified:** compiling `SmartSplit.sol` with solc-js 0.8.28 (Remix's compiler) as the single file `contracts/SmartSplit.sol` (as in Remix), optimizer 200, gives **identical executable bytecode** (1,672 bytes) to Hardhat. The only difference is the 53-byte **metadata hash** at the end, because it includes the source file path (`contracts/SmartSplit.sol` in Remix vs `project/contracts/SmartSplit.sol` in Hardhat 3). | The spec says "compiles identically". The executable code is identical. The metadata tail cannot be identical unless the file paths match. This is normal, and Etherscan verification still works. See `remix/REMIX_GUIDE.md`. |
| 12 | EVM version | `cancun`, the default for solc 0.8.28 in both Hardhat and Remix. Sepolia supports it. | Matching defaults means no extra setting is needed in either tool. |
| 13 | Frontend tooling | Vite 8 + React 19 + TypeScript (strict) + Tailwind CSS 4 (`@tailwindcss/vite` plugin) + ethers 6.17 + lucide-react. Lint uses **oxlint** (from the current `create-vite` template), run with `--deny-warnings`. | The current official scaffolds. oxlint includes the React-hooks rules. |
| 14 | Extra status `checking` | The status panel has one extra state before `awaiting-signature`: **checking**, while `staticCall` + `estimateGas` simulate the payment. If the simulation reverts, the panel shows "Blocked before sending" and MetaMask is never opened. | Makes the spec's "decode the custom error instead of opening MetaMask" visible to the user. |
| 15 | Read-only data without connecting | Network, contract info, `paymentCount` and **All payments** history load through MetaMask's provider as soon as MetaMask is installed, before the user clicks Connect (`eth_chainId` and `eth_call` don't need account permission). Sending always needs Connect. | Better demo: the examiner sees the history immediately. MetaMask never pops up automatically. |
| 16 | Async state pattern | A small `useAsyncData` hook stores each result **together with the key it was loaded for** (chain + account + contract), so a value from a previous account or network is never shown. | Avoids stale data after `accountsChanged` / `chainChanged` without page reloads, and passes the React lint rule against `setState` inside effects. |
| 17 | Block number for history | History queries end at `eth_blockNumber` read through `provider.send` (uncached), not `provider.getBlockNumber()`. | ethers caches `getBlockNumber()` for a short time. Right after a confirmation that made the history miss the newest payment (found by the browser smoke test). |
| 18 | Local chain in production build | Hardhat Local (31337) is offered only in `npm run dev`, or when `VITE_ENABLE_LOCAL_CHAIN=true`. A production build is Sepolia-only. | §5.3 says "enabled only in dev or when configured". |
| 19 | Gas warning | The "total + gas > balance" warning uses an **upper-bound** estimate of `50,000 + 40,000 × recipients` gas × current `maxFeePerGas`. | Based on measured costs (`TEST_RESULTS.md`). The real number comes from MetaMask at signing time. |
| 20 | Bundle size warning | `build.chunkSizeWarningLimit` raised to 700 kB. | ethers.js alone is about 400 kB minified. Splitting it gains little for a single-page demo. |
| 21 | Browser smoke test | Added an **optional** `frontend/e2e/ui-smoke.mjs` (`npm run e2e:local`). It drives the UI in headless Chrome against the local node, with a stand-in for `window.ethereum`. `puppeteer-core` is installed on demand with `--no-save`, so it is **not** a project dependency. | Lets the frontend be checked end to end without MetaMask. puppeteer-core's dependencies trigger `npm audit` warnings, and keeping them out leaves `npm audit` at 0 vulnerabilities. It does **not** replace the manual MetaMask checklist. |
| 22 | `REPORT.docx` | Not generated. | `pandoc` is not installed on this machine (`which pandoc` → not found). Generate it later with `pandoc docs/REPORT.md -o docs/REPORT.docx` once pandoc is installed. |
| 23 | npm cache workaround (build machine only) | During the build, npm was run with a temporary cache directory. | The user's `~/.npm` cache contains root-owned files (`EACCES`). It is not a project issue. The permanent fix (run by the student) is `sudo chown -R $(id -u):$(id -g) ~/.npm`. |
| 24 | Sepolia gas vs local gas | The frontend's gas-warning upper bound is chain-specific: `50k + 40k × n` on Hardhat Local and `300k + 230k × n` on Sepolia. All docs label gas figures as local or Sepolia. | The real Sepolia deployment used 2,875,494 gas vs 426,320 locally for identical bytecode. Sepolia's current upgrade (activated 2026-10-06) prices state creation much higher than the `cancun` rules simulated by the local chain. `eth_estimateGas` on the live contract: 449k (1 new recipient) to 4.27M (20 new). The contract is unchanged. |
